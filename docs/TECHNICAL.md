# 기술 메모

## 데이터
- 데이터는 `VC_20919/0.`~`4.`(1GB 분할) 아카이브. 머리: 파일 수, 파트 수, 파트별 섹터 수, 0x9C 부터 (해시, 크기, 섹터) 표. `tools/vc.py`
- 리소스 압축: 헤더 +0x10 이 0xFEEDBEEF 면 LZSS(해제 크기 u32, u32, 오프셋 비트수 u8, 플래그 LSB 먼저, 매치 u16 = 오프셋 n비트 + 길이-3). `tools/lz.py`
  한 파일에 압축 리소스가 이어지고 뒤에 비압축 꼬리가 붙는 경우가 많음.
- 문자열은 UTF-16LE 0 종료. 실행 파일·설명서(MANU, 미리 파싱된 HTML 노드)·퀴즈(TRIV)·로스터(ROST)·플레이북(PLAY)·레이아웃(MRKS/SCNE/TXTR 묶음)·기록 문구(DRCT, `^` 순차 치환).
  모두 칸 길이 안에서 제자리 교체하고, 바뀐 파일은 `VC_20919/4.` 끝에 덧붙인 뒤 아카이브 표·파트 크기·ISO9660·UDF 를 갱신.

## 글꼴과 한글 출력
- FONT 리소스: 범위 객체(첫/끝 글자, 범위 수, 범위 표, 기본 폭, 줄 높이, 어센트, 베이스라인) + 글리프 레코드(0x60 바이트: 진행폭, 4정점, UV) + PSMT4 텍스처.
- 글자 폭 함수와 글자 그리기 2곳은 범위 표에서 레코드를 찾고, 글자마다 그 글꼴의 텍스처 객체로 프리미티브를 시작함.
- 패치: "레코드 없음" 경로에서 0xE000~ 코드면 스텁이 공용 글꼴 fontk 를 찾아(힙 블록 체인에서 이름 `fontk`), 칸 위치(순번 ÷ 한 줄 글자 수)로 UV 를 계산하고
  그리는 글꼴의 'A' 글리프 높이·바닥으로 크기·베이스라인을 맞춘 레코드를 정적 버퍼에 만든다. 텍스처 선택 호출은 레코드가 그 버퍼면 fontk 텍스처를 돌려준다.
  코드 동굴은 실행 중 항상 0 인 정적 영역 0xBE9400. `tools/codepatch.py`
- 텍스처 헤더의 업로드 폭·높이(u16×2, 헤더 +0x7C)를 실제 크기로 맞춰야 VRAM 에 제대로 올라감.
- 메모리: 경기 중 여유가 약 0.8MB. fontk 는 텍스처만(512×512 4bpp, 칸 크기는 음절 수에 맞춰 16→13 자동).

## 주의한 점
- 한 단어 문자열 중 내부 키(애니메이션·사운드 이벤트, 텍스처 이름, 버튼·팀 코드 등)는 원문 유지. 레이아웃 리소스의 한 단어 라벨은 허용 목록만 번역.
- 작전명은 PLAY·실행 파일·DRCT·SCNE 에 같은 번역(같은 코드)을 넣어 이름 검색 일치 유지.
- 메모리 카드 슬롯 이름은 1바이트 변환 경로를 거쳐 한글이 깨지므로 원문 유지.
